# LP_SPEC.md — 需要検証LP要件書（Phase 1）

> 目的：開発着手前に「日本語ネイティブ品質 × 月980円 × 実技添削つきAI学習アプリ」への
> 需要をウェイトリスト登録率で測る。売るのではなく**登録させる**LP。

---

## 1. ターゲット（1次訴求）

- 25〜45歳の社会人。ChatGPT等を「触ったことはあるが、使いこなせている実感がない」層
- 高額AIスクール（数十万円）には手が出ない / 出したくない
- YouTubeやnoteで情報は見るが、行動と定着につながっていない
- ※ Lv3〜4（非エンジニア開発層）向け訴求はPhase 2以降。今回のLPでは混ぜない

## 2. 訴求の核（コピーの背骨）

「英語と同じで、AIも情報はもう溢れている。足りないのは**毎日続く練習環境**。」

3つの約束：
1. **1回3〜5分** — 通勤中・寝る前に終わる。学習コストを極小化
2. **書いて、直される** — 全レッスンに実技。あなたのプロンプトをAIが採点し、改善点を返す
3. **日本語ネイティブ品質・明朗会計** — 機械翻訳なし。月980円（予定）、いつでも解約可

## 3. コンプラ規律（既存LP規律を本件用に適用）

- **成果断定禁止**：「必ず使いこなせる」「絶対に身につく」NG →「〜を目指す」「〜のための」
- **料金は予定表記**：正式リリース前のため「月980円（予定・変更の可能性あり）」を明記
- **実績・口コミを創作しない**：ダミーの利用者数・受講者の声は置かない（まだ存在しないため）。
  代わりに「開発者自身の1年間の独学プロセスからカリキュラム化」という事実ベースの物語を使う
- **Coursiv等の競合名指し批判をしない**：対比表は「海外製学習アプリ」等の一般名詞で
- **プライバシーポリシー必須**（メールアドレス収集のため）。特商法表記は販売開始前のため不要
- ダミー値管理は既存規律踏襲：`GA4_ID = "G-XXXXXXXXXX"` 等、本物っぽい架空値を入れない

## 6. 計測と判定基準（Phase 1の出口）

- 広告：Google広告 or Meta広告、予算 5,000〜10,000円、期間3〜7日
- 計測：GA4イベント `waitlist_submit` をCVとして媒体側にもインポート
- 判定（クリック→登録率。仮基準として運用し、結果とともに見直す）：
  - **10%以上** → GO。Phase 2着手
  - **5〜10%** → コピー/訴求を1回改善して再走（再走は1回まで）
  - **5%未満** → 訴求かターゲットの見直し会議（WC）。安易に作り始めない
- 副次観測：どの広告文が刺さったか（=本開発時のメイン訴求の材料）

## 8. フォーム送信先（Phase 1の実装方針）

- 第一候補：**Formspree**（バックエンド不要・最速。無料枠の月間上限に注意、超えそうなら有料化）
- 代替：Astro APIルート + Supabase（Phase 2でどうせ使うため。ただし検証速度優先ならFormspree）
- どちらでもフロント側は `FORM_ENDPOINT` 差し替えだけで切替可能な作りにする

## 9. デザイン方針

- 既存LP（紺+赤の緊急対応系）とは別物。学習系の配色（例：濃紺 or 深緑ベース + 明るいアクセント1色）
- ゼロJS方針は踏襲しつつ、フォーム送信のみ最小限のJSを許可
- モバイルファースト（広告流入はほぼスマホ）
